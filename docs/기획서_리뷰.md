# 기획서 리뷰 — 구현 대조

**대상** `docs/기획서.md`(CLIPQ) · **기준** 2026-09-12 돌아가는 코드 · **남은 작업** `upgrade_plan.md`

## 결론

**파이프라인과 화면은 기획서대로입니다. 질문을 어디서 얻는가 하나가 다르고, 그 하나가
§01·§06 의 해자 서술을 떠받치고 있습니다.**

§06 다이어그램의 **아래 절반은 그대로 돕니다** — 질문 분류 → 임베딩 클러스터링 → 전사 →
상위 k개 → "이 구간이 실제로 답인가" LLM 판정 → 9:16 렌더 → 미응답 분리.
**위 절반은 코드가 한 줄도 없습니다** — 채널 OAuth 연동, 라이브 채팅 수집.

## 1. 질문의 출처

| | 기획서 | 구현 |
|---|---|---|
| 출처 | 라이브 채팅 실시간 폴링 | **우리 시청자 페이지에 직접 입력** |
| 시점 | 방송 중 | 다시보기, 아무 때나 |
| 선행 조건 | 방송 전 OAuth 연동 | 없음. 영상 URL 하나 |
| 타임코드 | 자동으로 딸려 옴 | 없음 — 임베딩 검색으로 찾음 |
| 로그인 | 없음 | 없음 (일치) |

**죽는 것** — 사전 연동 해자, Type A(밀도 급증), §09 데모의 밀도 그래프.
**사는 것** — 지나간 영상 어디에나 붙습니다. 라이브 방송을 잡을 필요가 없어 데모가 쉽고,
도입 마찰이 0이며, 질문하는 사람이 **지금 지원을 판단 중인 사람**입니다.

**권고.** Q-Rail 을 보여주는 화면이 아니라 **질문을 모으는 창구**로 올리고, 라이브 채팅은
향후 입력원으로 내립니다. 해자는 §07-5 **답변 라이브러리**를 앞으로 끌어옵니다 — 유튜브 API
특성에 기대지 않고 회차가 쌓일수록 커집니다. 이렇게 바꿔도 미응답 리포트·답변 라이브러리·
수요 벤치마크·사전 준비 도구는 **전부 그대로 삽니다.**

## 2. 사실이 다른 것 — 문서를 고쳐 주세요

| 문서 | 실제 |

| CLIPQ | 레포 `shorts_maker`, 화면 **TEASE**. 셋 중 하나로 |
| Next.js · Supabase · pgvector | **React+Vite · 자체 Postgres 17 · numpy 코사인**(N<1000 이라 1ms 밑) |
| FastAPI 폴링 워커 | 폴링 대상이 없음. 워커 1개짜리 메모리 잡 큐 |

| 본인 소유 채널만 처리 | **URL 로 받고 소유 확인이 없습니다** (결정 6) |
| CTA = 지원하기·신청하기 | **원본 영상의 그 지점으로 이동** (결정 1) |
| 90분 → 15~30분 | 미검증. 답변 1건에 428초 걸린 적 있음(모델 과부하). 빼거나 리허설 실측 후 |

## 3. 로드맵으로 옮겨 주세요 — 8일 안에 안 됩니다

채널 OAuth · 라이브 채팅 수집(**진행 중인 방송이 있어야 시험됨**) · Type A 밀도 급증 ·
Shorts 자동 업로드 · 신호 5단 중 2·3·4·5단 · 훅 카드 · CTA 오버레이 · Console(문서도 이미 제외).

**단, 0단(체크리스트 커버리지)과 1단(구체성 점수)은 넣을 만합니다.** 판정 프롬프트에 항목을
더하는 수준이라 호출이 안 늡니다. 특히 0단이 들어가면 **질문이 0건인 새 영상에서도 리포트와
클립이 나옵니다** — 5단으로 풀려던 콜드스타트를 더 싸게 해결합니다.

## 4. 문서에 없는데 이미 되는 것 — 발표 재료

| | 무엇 | 근거 |
|---|---|---|
| ① | **흩어진 답을 하나로 잇는 조합 클립.** 사이에 "45:26에서 이어집니다" 카드 | 실측: 25:48 + 45:26 → 18.93초 한 편. **경쟁 도구와 가장 다른 지점** |
| ② | **후보를 만들고 사람이 고르는 구조.** 대사 전문을 읽고 선택, 판정은 추천일 뿐 | §10 리스크 표의 "후보 5개, 사람이 고른다" 가 이미 돕니다. 다시 고르는 데 **LLM 비용 0** |
| ③ | **"이 영상엔 없지만 저 편에서 다룹니다"** — 같은 채널 다른 회차를 가리킴 | 5단의 사촌. 회차가 쌓일수록 강해짐. **영상이 한 편뿐이라 아직 못 봤습니다**(결정 4) |
| ④ | **퍼널·비용 계측.** 재생→완주→CTA→원본 이동→원본 재생을 **사람 수**로 | 문서는 Console 로 미뤘는데 이미 있음. 프롬프트·응답 원문도 보관 |

## 5. 결정해 주셔야 하는 것

| # | 결정 | 메모 |
|---|---|---|
| 1 | 🔴 **CTA 목적지** — 외부 전환 / 원본 유입 / 둘 다 | 제품의 목적함수입니다. 이걸 정해야 화면과 계측 방향이 잡힙니다. 외부 링크 추가 자체는 작은 작업 |
| 2 | **이름** — CLIPQ / TEASE / shorts_maker | 제출물 전체에 걸립니다 |
| 3 | **후보 개수 3 → 5** | 답변 1건당 LLM 호출 5회 → 7회. 무료 등급 기준 하루 4개 → 2.8개 |
| 4 | 🔴 **두 번째 영상** | ③을 보여주려면 같은 채널 영상이 한 편 더 필요. **전사에 수십 분** — 가장 먼저 확보해야 합니다 |
| 5 | **기회손실 추정치를 쓸까** | §07 "예상 이탈 지원자 약 18명" 은 전환 표본이 0이라 근거가 없습니다 |
| 6 | 🔴 **영상 소유를 뭐라고 말할까** | 아래 |

**6번.** §10 에 *"타인 영상 URL 입력은 아예 지원하지 않으며, 이 제약이 제품의 신뢰 축"* 이라고
쓰여 있는데 **구현은 반대**입니다. 게다가 데모 영상(쏘카 채용설명회)의 **채널 사용 허락이
아직 대기 중**입니다. 문서에 "아예 지원하지 않는다" 고 적어 두고 데모에서 URL 을 붙여 넣으면
그 자리에서 어긋납니다. "지금은 URL 입력, 소유 확인은 연동과 함께" 로 가는 편을 권합니다.
허락이 늦으면 대체 영상도 필요합니다 — 영상이 무엇이든 파이프라인은 같습니다.

## 6. 제출 전 우선순위

두 번째 영상 확보 → 미응답 리포트 1장 → 리허설 도구와 3회 → 질문당 평균 비용 →
CTA 구현 → 평가 세트. 근거와 크기는 `upgrade_plan.md` §5.

🔴 Gemini 가 "high demand" 오류를 몇 분씩 내는 구간이 있습니다. 라이브로 돌리는 데모 단계는
**미리 만들어 둔 결과를 보여주는 경로**를 함께 준비하는 편이 안전합니다.
