## 1. 이미 있는 네 가지 — 마무리와 노출

**기획서에 없는데 이미 도는 것들이다.** 넷 다 발표 재료이면서, 넷 다 마지막 한 걸음이 남았다.

### 1-1. 흩어진 답을 하나로 잇는 조합 클립

경쟁 도구와 **가장 눈에 띄게 다른 지점**이다. 기획서에는 언급이 없다.

**되는 것.** 조각 1~3개를 시간 순으로 잇는다. 사이에 0.4초 브릿지 카드가 들어가고
"45:26에서 이어집니다" 가 뜬다. 한 번의 인코딩으로 붙여서 코덱이 어긋날 여지가 없다.
실측(2026-09-11): 25:48 조각과 45:26 조각을 이어 **18.93초 · 1080×1920 · 48kHz 스테레오**,
브릿지 한글 정상.

**남은 것.**
- [ ] 🔴 **판정을 통과한 조합이 아직 없다.** 만든 것은 사람이 판정을 무시하고 고른 것이다.
      두 조각을 붙이면 두 번째가 지시어로 시작하기 쉬워 자립성에서 떨어진다
- [ ] 조합의 **첫 조각은 시작점 보정을 못 받는다** — 당기면 예산(30초)을 넘어 두 번째 조각이
      통째로 잘리고 그러면 조합이 아니게 된다. 지금은 그대로 두고 판정에 맡긴다
- [ ] 조각 상한이 3개라는 것이 화면에 안 보인다

### 1-2. 후보를 사람이 고르는 구조

기획서 §10 리스크 표의 *"AI가 후보 5개를 제시하고 사람이 고른다"* 가 이미 돈다.

**되는 것.** 한 번의 호출로 후보 N개를 만들고 병렬로 판정한 뒤 **대사 전문과 함께** 저장하고
멈춘다. 크리에이터가 읽고 고르면 그때 컷·렌더한다. 다시 고르는 데 **LLM 비용이 0**이다 —
범위도 대사도 판정도 이미 있다. 추천은 두 관문을 통과한 것 중 최고점이고 결정이 아니다.
보정 뒤 같아진 후보는 버린다.

**남은 것.**
- [ ] **개수를 3 → 5 로 올릴지 결정.** 판정 호출이 그만큼 는다(답변당 5회 → 7회).
      무료 등급 하루 20회 기준으로 하루에 답할 수 있는 질문이 4개 → 2.8개가 된다.
      `SHORTS_ANSWER_CANDIDATES` 로 바꾼다
- [ ] 5개로 올리면 넷째·다섯째의 `label` 은 모델이 짓는다 — 화면의 한글 표기표에 없어서
      영어 낱말이 그대로 보인다
- [ ] 후보 화면을 실사용으로 본 것이 아직 한 번뿐이다

### 1-3. "이 영상엔 없지만 저 편에서 다룹니다"

데모 시나리오 6이고, **가장 똑똑해 보이는 장면**이다.

**되는 것.** 같은 채널의 발행된 다른 영상 구간을 답하기 직전에 자동 인덱싱하고, 이 영상의
최고점보다 가까우면 그 영상을 가리킨다. 시청자 화면에 안내가 뜬다. 절대 임계값을 쓰지 않는
이유는 실측에서 유사도가 0.502~0.755 좁은 띠에 몰렸기 때문이다.

**남은 것.**
- [ ] 🔴 **영상이 한 편뿐이라 실제로 본 적이 없다.** 두 번째 영상이 있어야 이 기능이
      화면에 나타난다. **제출 전 최우선 준비물이다**(§5)

### 1-4. 퍼널과 비용

기획서는 이걸 Console 로 미뤄 뒀는데(MVP 제외) 이미 있다.

**되는 것.** 이벤트 7종을 쌓고 클립별 퍼널을 **사람 수**로 센다(재생 → 완주 → CTA →
원본 이동 → 원본 재생). 숫자가 적을 때 비율을 쓰지 않는다. 총비용과 단계별 토큰·지연,
그리고 **프롬프트와 원본 응답**을 남긴다.

**남은 것.**
- [x] **질문당 평균 비용** — 완료 2026-09-12. 🔴 나눗셈 하나가 아니었다. `classify` 와
      `retrieve` 가 **run 에 안 묶여 있어서** 어느 질문 때문에 일어난 호출인지 알 수 없었다.
      그것부터 붙이고, 비용을 **회차 준비와 질문 답변으로 갈랐다** — 합쳐서 질문 수로 나누면
      질문이 하나일 때 전사·분할비가 통째로 그 질문에 얹힌다.
      분모는 "답한 질문" 이 아니라 **"답하기를 돌린 질문"** 이다. 못 답한 것도 돈을 썼다.
      기준 경로(크리에이터가 자기 기준으로 뽑은 것)의 run 은 분모에서 뺀다.
      **실측(영상 1편, 95분)**: 회차 준비 260원 · 질문 답변 72원(4건) · **질문당 18원**.
      🔴 전사는 로컬 연산이라 API 비용이 0이다 — 이 숫자만 보고 "전사가 싸다" 로 읽으면 안 된다
- [ ] **사람·모델 판정 일치율** — 양쪽 다 저장되는데 계산하는 코드가 없다. tease §11 이
      "첫 품질 지표" 라고 부른 것이다
- [ ] 규칙·LLM 라우팅 일치율 — `params->>'rule' = params->>'route'` 한 줄이다
- [ ] 실제 시청자 이벤트가 6건뿐이다. 리허설에서 쌓인다

### 2-1. 🔴 CTA 목적지 — 제품 결정 (PM)

### 2-2. 미응답 질문 리포트 (기획서 Type C)

**기획서가 부산물이자 갱신의 근거로 삼은 것**이고, 데이터는 이미 다 있다.

- [x] **완료 2026-09-12.** `answers/report.py` + `GET /api/sources/{id}/report` + 스튜디오 **리포트 탭**.
      🔴 "못 답함" 을 **셋으로 갈랐다** — 영상에 없다(UNANSWERABLE) / 아직 안 눌렀다(OPEN) /
      만들었다 물렸다(DECLINED). 뜻이 달라서 크리에이터가 할 일도 다르다: 앞의 것은 다음 회차
      큐시트고, 가운데는 버튼만 누르면 되고, 뒤의 것은 다시 만들어야 한다.
      🔴 **판정 사유를 함께 준다.** "답할 구간 없음" 딱지만으로는 영상이 정말 안 다룬 건지
      검색이 빗나간 건지 구분할 수 없다.
      🔴 **"글로 복사" 버튼**이 이 탭의 산출물이다 — 담당자가 윗선에 보내는 것은 화면이 아니라

## 3. 감사에서 남은 것 (기획서와 무관)

2026-09-09 감사 목록의 잔여분이다. 자세한 근거는 `handoff.md` §7.

- [ ] 🔴 **답변 경로 평가 세트** — `eval/questions.json` 에 `type`·`expect` 가 없고
      `sm tease eval-answer` 가 없다. 라우팅·후보·조합·답변 불가가 질문 세트로 측정된 적이 없다.
      **본선 발표의 품질 근거가 여기서 나온다**
- [x] 🔴 **M9 리허설 도구** — 완료 2026-09-12. `sm tease check | seed | unseed | reset`.
      🔴 **pg_dump 스냅샷을 쓰지 않는다.** 앱 이미지에 없기도 하지만, 그보다 **되돌리고 싶은 것이
      DB 전체가 아니기 때문**이다. 전사·구간 분할·임베딩은 편당 수십 분이라 리허설마다 날리면
      리허설 자체를 못 한다. 그래서 표적 초기화다.
      - `check` — 데모 8단계의 전제를 한 번에 본다. 🔴 막힌 게 있어도 종료 코드는 0이다.
        점검 도구가 실패한 게 아니라 결과를 보고한 것이다
      - `seed` — 질문을 좋아요와 함께 넣는다. **[집계]는 하지 않는다** — 그 버튼을 누르는 것이
        데모 2단계다. 좋아요를 넣는 이유는 수요 순 정렬이 화면에 보여야 하기 때문이다
      - `unseed` — **시드한 것만** 지운다(`viewer_id` 표식). 진짜 시청자 질문과 섞이면 수요
        순위가 거짓이 되는데, 그게 이 제품이 보여주려는 바로 그 숫자다
      - `reset` — 회차를 되돌린다. 🔴 `stage_calls` 를 **run 보다 먼저** 지운다 —
        `run_id` 가 `on delete set null` 이라 순서를 거꾸로 하면 답변 비용이 **회차 준비 비용으로
        둔갑하고**, 리허설을 돌릴수록 준비비가 불어나는 거짓 숫자가 만들어진다
- [ ] 🔴 **리허설 3회** — 도구는 생겼고 아직 한 번도 안 돌렸다. 시나리오 1~8 을 시간 재며.
